# Shalin Naidoo | Writing

A personal blog built with React, TypeScript, and Vite. The homepage opens directly into a grid of posts, with articles at `/writing/:slug` and a contact form at `/contact`.

```sh
npm install
npm run dev
```

Validate with `npm run build` and `npm run lint`.

- `src/App.tsx`: the post index, article layout, and contact page.
- `src/components/ContactForm.tsx`: the contact form and its sending, sent, and error states.
- `worker/index.ts`: the Worker behind `/api/contact`, which emails form messages to you.
- `worker-configuration.d.ts`: Worker types generated by `npm run cf-typegen`. Rerun it after
  changing `wrangler.jsonc`.
- `src/posts.ts`: article content and metadata, ordered newest first.
- `src/App.css`: responsive editorial layout and component styling.
- `src/index.css`: global typography and dark color tokens.
- `public/fonts/`: self-hosted Poppins for the site, plus the Geist, Geist Mono, and
  Instrument Serif files the brand digest uses, with their licences.
- `docs/brand-digest.html`: an offline reference for the earlier Louder palette,
  typography, components, contrast, and copyable CSS tokens. Open the file directly
  in a browser. It stays in the repo and is not included in the production build.

The look follows the LocalThunk blog landing page: dark slate (`#1a242c`),
off-white text (`#f3f6f8`), Poppins, and a grid of posts showing a date above a
large title. Selected text is highlighted in the yellow (`#f8ce5e`) from the fire
dog favicon in `public/favicon.svg`. The site always uses this dark palette.

## Cloudflare Workers

Cloudflare Workers serves the site with Static Assets. `wrangler.jsonc`
publishes `dist` and enables the SPA fallback so direct visits and refreshes at
`/writing/engineering-the-feedback-loop` load the React application. The Worker script in
`worker/index.ts` only runs for `/api/*` requests; everything else is served straight from
the static assets.

Use the Node.js version in `.node-version` and install dependencies with `npm ci`.

```sh
# Build and preview with Cloudflare's local runtime
npm run preview

# Authenticate once, then build and deploy
npx wrangler login
npm run deploy
```

To validate deployment configuration without publishing:

```sh
npm run build
npx wrangler deploy --dry-run
```

Connect the Worker to GitHub under **Settings > Builds** using these settings:

| Setting | Value |
| --- | --- |
| Repository | `shalinbtw/portfolio` |
| Production branch | `main` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Root directory | Repository root |

The Worker name in Cloudflare must match `portfolio` in `wrangler.jsonc`.

### Contact form

The form posts to `/api/contact`. The Worker checks that the request came from this site,
limits each IP address to 5 messages a minute, ignores bots that fill a hidden field, and
validates the fields. It then emails the message from `contact@shalinbtw.com` through
Cloudflare Email Routing. Reply-To is set to the sender, so replying in your mail client
answers them directly.

Your inbox address is stored only as the `CONTACT_TO` Worker secret, never in this public
repository. One-time setup:

1. In the Cloudflare dashboard, open **shalinbtw.com > Email > Email Routing** and enable it.
   This adds the MX and SPF DNS records Cloudflare needs.
2. Under **Destination addresses**, add the inbox that should receive messages and confirm
   the verification email.
3. Store that address as a secret (Wrangler prompts for the value):

   ```sh
   npx wrangler secret put CONTACT_TO
   ```

To test locally, run `npm run preview` with a `.dev.vars` file containing
`CONTACT_TO=inbox@example.com`. Wrangler does not send real email in local development; it
logs each message and saves the text under `.wrangler/tmp/email/`. The Vite dev server
(`npm run dev`) does not run the Worker, so the form shows its error message there.

Production: <https://shalinbtw.com> and <https://shalinnaidoo.dev>. Both domains serve
the same site directly.

The custom domains are declared in `wrangler.jsonc`. The `workers.dev` address and
version preview URLs are disabled, matching the Cloudflare dashboard settings.

The former Cloudflare Pages project has been removed. Use the Worker's deployment
history in Cloudflare for rollbacks.
